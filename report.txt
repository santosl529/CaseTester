2. WHAT CHANGED
==============================================================================

2.1 Behavior spec (docs/interviewer-behavior.md, now v4.1)
  - Your v3.4 rewrite integrated, renumbered v4.1 (the repo copy was already
    v4). My critiques folded in: data-request detection is a soft signal;
    deferrals must be settled before the recommendation ask; a worked example
    for "time warning + open data request"; reconciliation is an LLM pass.
  - The run-4 account in Rule 11 corrected against the transcript: four
    ignored requests, not two (menu prices asked three times); the "waste
    narrative" critique rested on a COGS breakdown the case doesn't have, so it
    was fair; the real gap was the withheld price data.
  - Rule 10's enforcement note kept as it was (the paste would have reverted it
    to describe a check that never existed).

2.2 Data requests (Rule 11)
  - A Haiku classifier logs every candidate data request and how the next
    interviewer turn handled it (release / refuse / defer / clarify / none).
  - One request can map to several ledger items ("what's inside COGS?" covers
    both the bean share and other inputs).
  - A "classified" marker per exchange, so scoring can re-check any exchange the
    background pass missed.
  - Still-unreleased requests are reminded to the interviewer each turn.
  - Before any recommendation ask, up to two open ledger requests are released
    ahead of the ask — what the candidate asked for that turn first, then the
    most recent asks.
  - Showing an exhibit counts as releasing the ledger items it displays.
  - Stating a figure is no longer logged as a request.

2.3 Scoring and the report
  - The judge now sees data the candidate asked for and never got as its own
    coverage-gap section, and is told never to charge the candidate for it.
  - New final pass (reconciliation): merges a point stated as both a strength
    and a weakness within one dimension, drops criticism that rests on data the
    candidate asked for and never got, logs points repeated across 3+
    dimensions. Its parser was broken on first contact with live output (the
    model writes prose before the JSON) — found by replaying with raw logging
    and fixed.
  - Feedback points with no real candidate quote are dropped.
  - Transcript repair cuts any interviewer turn where the model wrote the
    candidate's side.
  - The judge and reconciliation prompts must say "the candidate" / "you",
    never he/his or she/her (prompt-level only).

2.4 Live interviewer (orchestrator)
  - Phase repair: the phase now moves forward on what visibly happened (data
    released, exhibit shown, brainstorm asked, recommendation asked). Before
    this, every live run sat in STRUCTURE for the whole case.
  - Guard against the interviewer writing the candidate's answer: stop
    sequences on the model call plus a cut in the runner. (Live run 58cb8061
    had the interviewer write the candidate's brainstorm, which was then
    scored "strong".)
  - On the scripted recommendation-ask turn, a question the model ended on is
    dropped so only one question is asked.
  - Every ending turn gets a closing line; after time-up the prompt forbids
    new feedback, corrections, or analysis.
  - The number-source check accepts figures from every candidate turn, the
    case prompt, and the change inside a released value (58% vs 42% → 16).
